# Vanguard Tactics — 게임 디자인 문서 (GDD) v0.1

> 유니콘 오버로드의 **조건부 택틱 × 전열/후열 부대 전투** + 밴티지 마스터의 **실시간 거점 확장 전략**을 결합한 웹 기반 멀티플레이 전략 게임.
> 한 판 20분. 픽셀/로우폴리 아트. AI 봇 내장.

---

## 1. 한 줄 요약 (Pitch)

각자 본진에서 시작해 실시간으로 거점을 늘리고 부대를 키운다. 부대끼리 마주치면 전투 영역이 열리고, 전열/후열 배치와 조건부 택틱에 따라 자동으로 전투가 진행된다. 전투의 승패는 **피해가 아니라 남은 사기(Morale)** 로 갈리며, 패배한 부대는 와해되어 가장 가까운 거점으로 퇴각한다. 매치 목표를 먼저 달성하는 쪽이 승리한다.

## 2. 핵심 기둥 (Design Pillars)

1. **배치가 곧 전략** — 같은 유닛도 전열/후열에 따라 전혀 다른 행동을 한다. 편성 화면에서 승부의 절반이 결정된다.
2. **자동 전투, 수동 설계** — 플레이어는 전투 중 조작하지 않는다. 대신 택틱(조건 → 행동)을 미리 설계한다. 유니콘 오버로드식.
3. **실시간 전략, 멈추지 않는 세계** — 전투가 벌어져도 맵은 계속 흐른다. 여러 전투가 동시에 진행될 수 있다.
4. **사기가 승패를 가른다** — 피해를 덜 받았어도 사기가 더 깎이면 진다. 이는 "뭉개기" 대신 **흐트러뜨리기**를 보상한다.
5. **짧고 밀도 높은 한 판** — 20분 안에 확장 → 충돌 → 결판.

## 3. 매치 구조 (Macro Layer) — 밴티지 마스터 계승

### 3.1 맵
- 2인(1v1) 기준으로 설계. 양 끝에 **본진(Home Base)**, 사이에 **중립 거점(Outpost)** 8~12개. (4인 FFA/2v2는 후순위)
- 거점은 **경로(edge)** 로 연결된 노드 그래프. 부대는 경로를 따라 실시간 이동.
- 거점 타입(제안):
  | 타입 | 효과 |
  |---|---|
  | 보급소 | 자원 수입 ↑ |
  | 병영 | 해당 거점에서 소환 가능 유닛 풀 확장 |
  | 감시탑 | 주변 경로 시야 |
  | 성소/제단 | 특정 매치 목표 전용 (예: 보유 시간 누적) |
  | 요새 | 주둔 부대의 전투 시작 사기 보너스 |

### 3.2 거점 점령
- 중립/적 거점(본진 제외)에 부대가 도착해 **일정 시간 머무르면 점령**. 적 부대가 동시에 있으면 전투가 먼저 발생.
- **상대 본진은 점령 불가** (엘리전 모드 제외). 본진 앞까지 밀어붙여도 "승리"는 목표 달성으로만 가능. → 스노우볼이 굴러도 역전의 여지를 남긴다.

### 3.3 자원과 부대 양성
- 단일 자원 **군자금(Gold)**. 거점 수에 비례해 초당 수입. (밴티지 마스터의 MP와 동일한 역할)
- 유닛은 **본진 또는 병영 거점에서 소환**, 소환된 유닛은 그 거점에 주둔한 **부대(Squad)** 에 편성.
- 유닛마다 **소환 비용**이 다르며, 진열을 강제로 바꾸는 유닛(§5.4)은 고비용 티어.
- 부대 수 상한: 동시 보유 **최대 N개** (제안: 5). 부대당 유닛 상한은 §4.1.

### 3.4 매치 목표 (Objectives)
매치 시작 시 하나가 선택(또는 로비에서 지정). 모두 **20분 내 결판**을 전제로 수치 조정.
| 목표 | 승리 조건 | 비고 |
|---|---|---|
| 점령전 | 거점 과반을 **연속 T초** 보유 | 기본 모드 |
| 성소 쟁탈 | 중앙 성소 보유 시간 누적 **X초** 선점 | 중앙 집중형 교전 유도 |
| 수송전 | 수송 유닛을 지정 경로 끝까지 호위 성공 | 비대칭/교대 라운드 |
| 전멸전(엘리전) | 상대 본진 점령 | **유일하게 본진 점령이 허용되는 모드** |
| 시간 종료 | 20분 경과 시 **보유 거점 수 → 총 사기 → 군자금** 순 타이브레이크 | 모든 모드 공통 |

## 4. 부대와 편성 (Squad & Formation)

### 4.1 부대 규격
- 부대 = **2열 × 3칸 = 최대 6유닛** (전열 3, 후열 3). *(미결: 2×2=4로 축소 가능)*
- 각 칸은 비워둘 수 있다. 빈 전열 칸은 상대 전열 공격이 **후열로 흘러들어가는** 구멍이 된다.
- 부대장(Leader) 1명 지정 → 부대 이동속도/시야/사기 상한 등에 리더 효과.

### 4.2 전열/후열 행동 분기 — 이 게임의 핵심
각 유닛은 두 벌의 **행동 세트**를 가진다.
```
Unit
 ├─ 전열 세트 (Front Set)
 │    ├─ 행동 횟수: 예) 2회
 │    └─ 스킬 목록 + 기본 택틱
 └─ 후열 세트 (Back Set)
      ├─ 행동 횟수: 예) 1회
      └─ 스킬 목록 + 기본 택틱
```
- **행동 횟수(Action Count)** 가 열에 따라 다르다. 예) 창병: 전열 2회 찌르기 / 후열 1회 장창 관통. 궁수: 전열 1회 근접(약함) / 후열 2회 사격.
- 전투 중 자신이 어느 열에 있는가는 **전투 시작 시의 배치 + 전투 중 강제 이동(§5.4)** 으로 결정된다.
- 따라서 "상대 전열을 후열로 밀어넣거나 후열을 끌어내는" 능력은 **상대 유닛의 행동 세트 자체를 바꿔버리는** 강력한 효과 → 고비용 유닛만 보유.

### 4.3 택틱 (Tactics) — 유니콘 오버로드 계승
- 유닛마다 **우선순위 목록**: `[우선순위] 행동 ← 조건1 AND 조건2`
- 전투 중 자기 차례가 오면 **위에서부터 조건이 만족되는 첫 행동**을 실행. 아무것도 만족하지 않으면 기본 공격.
- 조건 예시 (초기 30종 내외):
  - 대상: `HP < 25%`, `사기 최저`, `후열 우선`, `전열 우선`, `비행`, `중장갑`, `마법사`, `리더`
  - 상황: `아군 전열 빈 칸 있음`, `적 2명 이상 인접`, `내 행동 2번째`, `전투 시작 직후`, `아군 사기 < 50%`
  - 자기: `내가 전열에 있음`, `내가 후열로 밀려남`
- 전열 세트와 후열 세트의 택틱은 **따로** 설정. 같은 유닛이라도 배치와 택틱 조합으로 전혀 다른 전개가 가능해야 한다.
- 택틱 템플릿 저장/불러오기 (로비에서 프리셋 관리).

### 4.4 편성 타이밍
- 편성은 **거점에서만** 가능. 이동 중/전투 중 변경 불가.
- 패배 후 퇴각한 부대는 **와해 상태(Scattered)** — 재편성 전까지 전투 불가, 점령 불가.

## 5. 전투 (Micro Layer)

### 5.1 전투 발생과 전투 영역
- 두 적대 부대가 같은 경로/거점에서 **접촉**하면 전투 발생.
- 전투가 시작되면 그 부대들은 맵 상에서 **전투 영역(Battle Pocket)** 에 들어간다.
  - 영역 안의 부대는 이동·점령 불가, 외부 간섭 불가(초기 버전). *(미결: 증원 부대 합류 허용 여부)*
  - **맵 시간은 멈추지 않는다.** 전투는 자기 속도로 진행되고 끝나면 결과가 맵에 반영된다.
- 플레이어 UI:
  - 맵에 전투 아이콘 표시 + 우측 **전투 일람(Battle List)**.
  - 아이콘/일람 클릭 → 진행 중인 전투 화면을 **관전**. 강제 전환 없음. 관전 중에도 맵 조작 가능(분할 또는 오버레이).
  - 이미 끝난 전투도 일정 시간 **리플레이** 가능 (결정론적 시뮬이므로 저장 비용 ↓).

### 5.2 전투 진행
1. **초기화**: 양측 배치 확정, 각 유닛의 열에 따른 행동 세트 로드, 행동 횟수 충전.
2. **행동 순서**: 모든 유닛을 **속도(Initiative)** 내림차순으로 정렬해 턴 큐 구성. 행동 횟수가 남은 유닛만 큐에 남는다.
3. **행동 실행**: 큐 선두 유닛이 택틱 평가 → 행동 → 행동 횟수 -1 → 큐 재정렬(속도 보정/상태이상 반영).
4. **종료**: 양측 모두 행동 횟수 소진 **또는** 한쪽 사기 0 **또는** 한쪽 전멸.
5. **판정**: §5.3.
- 한 전투는 실시간 기준 **15~40초**. 연출 속도는 관전 여부와 무관하게 동일(관전은 그냥 보는 것).

### 5.3 사기(Morale)와 승패
- 부대마다 **사기 게이지** (제안: 기본 100, 요새/리더/상태로 보정).
- 사기 감소 요인:
  | 사건 | 감소량(제안) |
  |---|---|
  | 유닛 피해 | 피해량에 비례 (소량) |
  | 유닛 전투불능 | 큼 (리더면 ×2) |
  | 강제 진열 변경 당함 | 중간 |
  | 회피/방어/가드 성공 | 상대 사기 소폭 감소 (기세) |
  | 전투 시작 시 수적 열세 | 초기 패널티 |
- **승패 = 전투 종료 시 남은 사기가 많은 쪽**. 피해량은 직접 비교하지 않는다. (동률: 무승부 → 양측 제자리, 재접촉 시 재전투)
- 설계 의도: 적 한 명을 집중 처치하거나 리더를 끊거나 진열을 무너뜨리는 **"흔들기"** 가, 고르게 때리는 것보다 가치 있게.

### 5.4 진열 강제 변경 (Formation Break)
- 종류: `끌어내기(Pull)` 후열→전열, `밀어넣기(Push)` 전열→후열, `자리바꿈(Swap)`, `돌파(Breach)` 전열 무시 후열 직격.
- 변경된 유닛은 **즉시 그 열의 행동 세트로 전환**되며 남은 행동 횟수는 새 세트 기준으로 재계산(제안: `남은 비율 × 새 세트 횟수`, 내림).
- 보유 유닛: 기병(돌파), 쇠사슬병(끌어내기), 거인/공성(밀어넣기) 등 — 모두 **고비용 티어**. 매치당 소환 수가 자연히 제한되도록 비용 설계.

### 5.5 전투 결과 반영
- **승리 부대**: 즉시 다음 명령 수행 가능 (HP/사기는 회복 없이 유지 → 연전 리스크).
- **패배 부대**: 가장 가까운 **아군 거점**으로 자동 퇴각. 퇴각 중 **와해 상태**: 전투 불가(접촉 시 즉시 추가 사기 손실/유닛 손실 판정), 조작 불가. 거점 도착 후 재편성 필요.
- 전투불능 유닛: 사망이 아니라 **부상** → 거점 복귀 시 비용/시간 지불로 복귀. *(미결: 영구 사망 여부)*

## 6. 유닛 (초기 로스터 제안, 12종)

| 유닛 | 비용 | 전열 세트 | 후열 세트 | 역할 |
|---|---|---|---|---|
| 보병 | 1 | 베기 ×2, 가드 | 투창 ×1 | 기본 벽 |
| 창병 | 1 | 찌르기 ×2 (대기병) | 장창 관통 ×1 (전열 넘어 타격) | 대기병 |
| 궁수 | 1 | 단검 ×1 (약) | 사격 ×2 (후열 우선 선택 가능) | 원거리 딜 |
| 도끼병 | 2 | 강타 ×1 (가드 무시) | — (행동 0, 후열이면 무용) | 중장갑 파쇄 |
| 방패병 | 2 | 가드 ×3 (사기 역전 특화) | 사기 고무 ×1 | 사기 탱커 |
| 치유사 | 2 | 응급 ×1 | 치유 ×2, 사기 회복 ×1 | 지속력 |
| 마법사 | 2 | 화염 ×1 | 광역 ×1, 열 전체 타격 | 광역 |
| 경기병 | 3 | 돌파 ×1 (전열 무시) | 기동 사격 ×1 | 후열 암살 |
| 쇠사슬병 | 3 | 끌어내기 ×1 + 베기 ×1 | 투척 ×1 | 진열 파괴 |
| 거인 | 4 | 밀어넣기 ×1, 내려치기 ×1 | — | 진열 파괴 |
| 전령 | 2 | — | 사기 고무 ×2 (리더 효과 증폭) | 리더 보조 |
| 수송차 | 1 | — | — | 수송전 전용 |

(행동 횟수·수치는 전부 플레이테스트로 조정. "후열 세트 없음"인 유닛은 밀려나면 **완전히 무력화**되는 것이 의도.)

## 7. 20분 페이싱 (목표 곡선)

| 시간 | 상태 |
|---|---|
| 0~3분 | 초기 부대 1개로 인접 중립 거점 2~3개 확보. 첫 소환 선택. |
| 3~8분 | 중앙 거점에서 첫 접촉. 진열 파괴 유닛은 아직 못 뽑는 비용 구간. |
| 8~14분 | 거점 5~7개 보유, 부대 3~4개, 고비용 유닛 등장. 전투 2~3개 동시 발생. |
| 14~20분 | 목표 달성 카운트다운 싸움. 역전은 "거점 되찾기"로만 가능하게. |
| 20분 | 타이브레이크. |

튜닝 지표: 평균 매치 길이 18~22분, 첫 전투 발생 ≤ 5분, 매치당 전투 수 8~15회.

## 8. AI 봇

- 봇은 **플레이어와 동일한 명령 인터페이스**만 사용(치팅 없음).
- 계층:
  1. **전략층**: 거점 가치 평가(거리·타입·목표 기여) → 확장/방어/견제 목표 선택.
  2. **편성층**: 상대 부대 정보(정찰 범위 내)에 대한 카운터 편성 룰 + 택틱 프리셋 선택.
  3. (전투 중 조작은 없으므로 전투 AI는 택틱 시스템 자체.)
- 난이도: 반응 지연·정찰 활용도·프리셋 품질로 구분.
- 용도: 연습 모드, 매치 상대 부재 시 대체, 밸런스 자동 시뮬(봇 vs 봇 수천 판으로 승률 점검 — 결정론적 시뮬이라 헤드리스 가능).

## 9. 아트 & UI

- **픽셀 아트** 우선 (레퍼런스: 오우거 배틀 64/택틱스 오우거 계열). 로우폴리는 2차 옵션.
- 맵 화면: 쿼터뷰 또는 탑뷰 노드맵, 부대는 아이콘+숫자, 전투 중 아이콘 점멸.
- 전투 화면: 2열×3칸 양측 대치, 유니콘 오버로드식 결과 미리보기는 **없음**(실시간이라 불가) → 대신 편성 화면에서 "가상 전투 시뮬" 버튼 제공.
- 편성 화면: 유니콘 오버로드 Unit Details 유사 — 좌측 격자, 우측 택틱 우선순위 테이블(전열/후열 탭).

## 10. 기술 구조 (제안)

- **TypeScript 모노레포**
  - `packages/sim` — 맵·전투 **결정론적 시뮬레이션** (순수 함수, 고정 틱, 시드 RNG). 서버/클라/봇/테스트가 공유.
  - `packages/server` — Node + WebSocket. **서버 권위(authoritative)**: 명령을 받아 틱 진행, 상태 스냅샷/델타 브로드캐스트.
  - `packages/client` — 웹 클라이언트. 렌더링 **PixiJS**(픽셀 아트에 적합). 전투 관전은 서버가 보낸 전투 시드+입력으로 로컬 재생.
  - `packages/bot` — §8 AI. 서버 내부 또는 별도 프로세스.
  - `packages/data` — 유닛/스킬/조건/맵 정의(JSON). 밸런스 수정이 코드 변경 없이 가능.
- 전투를 **시드 기반 결정론**으로 두는 이유: 관전/리플레이/봇 시뮬/디싱크 검증이 모두 공짜.
- 틱레이트: 맵 10 tick/s, 전투는 독립 틱(행동 단위 이벤트 로그).

## 12. 미결 사항 (결정 필요)

1. 부대 규격 2×3 vs 2×2.
2. 전투 중 증원 부대 합류 허용 여부(허용 시 전투 영역이 "열린" 구조가 됨).
3. 전투불능 유닛: 부상 복귀 vs 영구 사망.
4. 플레이어 수: 1v1 전용으로 시작할지, 2v2를 맵 설계 단계부터 고려할지.
5. 아트: 픽셀 확정 vs 로우폴리 병행.
6. 관전 UI: 오버레이 vs 화면 분할.
