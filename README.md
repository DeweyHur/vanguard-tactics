# Vanguard Tactics

유니콘 오버로드의 **전열/후열 × 조건부 택틱** 부대 전투와 밴티지 마스터의 **실시간 거점 쟁탈**을 결합한 웹 전략 게임 프로토타입. 기획은 [`docs/GDD.md`](docs/GDD.md).

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 — 봇 상대 싱글 매치
npm test           # sim 헤드리스 테스트 (전투 엔진 / 매치 규칙)
npm run sim:bench -- 30 domination   # 봇 vs 봇 N판 밸런스 벤치
npm run build      # packages/client/dist
```

## 구조

```
packages/
  sim/     결정론적 시뮬레이션 (순수 TS, DOM 의존 없음) — 서버/클라/봇/테스트가 공유
    src/data/   유닛 12종, 스킬, 택틱 조건 30종, 맵
    src/battle.ts  전투 엔진: 행동 순서, 택틱 평가, 사기, 진열 강제 변경
    src/match.ts   매치: 노드 그래프 이동, 점령, 자원, 전투 포켓, 퇴각/와해, 목표
  bot/     플레이어와 동일한 Command 인터페이스만 쓰는 AI (+ 벤치 스크립트)
  client/  Vite + Canvas 2D 클라이언트 (맵 / 편성 / 택틱 편집 / 전투 관전 오버레이)
```

### 핵심 규칙 (구현 기준)
- 부대 = 2열 × 3칸. 유닛마다 **전열 세트 / 후열 세트**가 따로 있고 행동 횟수·스킬·택틱이 다르다 (`UnitDef.front / back`).
- 택틱 = `[스킬, 조건1, 조건2]` 우선순위 목록. 위에서부터 조건을 만족하는 첫 행동 실행. 조건1이 1차 정렬 키.
- 전투 승패 = 종료 시 **남은 사기**. 피해·전투불능·진열 변경·가드 성공 등이 사기를 깎는다.
- `pull / push / breach` 스킬(쇠사슬병·거인·경기병)이 상대 열을 강제로 바꾸고, 바뀐 유닛은 즉시 그 열의 세트로 전환된다.
- 맵은 멈추지 않는다. 전투는 시드 기반으로 즉시 계산되고(`runBattle`), 행동 수에 비례한 시간 동안 **전투 포켓**에 묶였다가 결과가 반영된다. 클라이언트는 이벤트 로그를 맵 시간에 맞춰 재생한다 → 관전/리플레이가 공짜.
- 패배 부대는 가장 가까운 아군 거점으로 자동 퇴각 → **와해** → `reform` 명령으로 재편성해야 움직인다.
- 상대 본진은 전멸전 모드에서만 점령 가능.

### 멀티플레이로 가는 길
`Match.command(player, cmd)` + `Match.tick()`이 전부라서, 서버는 두 클라이언트의 명령을 받아 틱을 돌리고 상태를 브로드캐스트하면 된다 (`packages/server` 예정). 전투는 시드만 보내면 클라이언트가 동일하게 재생할 수 있다.
